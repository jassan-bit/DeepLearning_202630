# Matriz documental R3 y viabilidad de candidata

No hay una candidata habilitada hoy para confirmación. V3 conserva NO-GO y V4 el abandono de su receta; el control MSE-only no se promueve por ganar el desarrollo. Este dictamen no afirma que sea imposible una contribución futura.

Se leyó el PDF original de 60 páginas y se reusó la auditoría primaria previa, contrastando sus conclusiones con los recibos actuales y los capítulos 06, 07, 08 y 14. El PDF tiene SHA256 `d6048aebd7b3db85a59231a5a89b01bc3f8ad8cb581a96b462e341d21ff1f364` y 922729 bytes. Los hashes de todos los insumos son de sus bytes reales en `INPUT_BYTES_MANIFEST.json`. `2fbab63` es la referencia recibida del coordinador; el snapshot no contiene `.git` y no se presenta como checkout verificado.

La guía exige ≥0,90 de potencia por contraste y reportar la conjunta, ≥5 semillas piloto y ≥10 finales o más por potencia, tres pruebas distintas pertinentes y al menos una global/con control múltiple, familia completa y las condiciones simultáneas de medias, efecto/IC, adecuación, robustez y adicionales. No exige universalmente conjunta ≥0,90, tres nulos theta≤δ o una familia global de 252 componentes. Las elecciones del proyecto se separan en `PROJECT_CHOICES_NOT_UNIVERSAL_GUIDE.json`.

R1 de V3 tiene dictamen técnico IA favorable y acotado; no es aceptación docente. R2 conserva la comprensión/defensa pendiente de observación. El fracaso de desarrollo no refuta novedad, y una defensa no observada no prueba copia. La guía §14.1 p42 sólo evalúa R3 cuando se cumplen R1/R2; una condición pendiente no se convierte aquí en «no», ni se asigna nota/tope. Ningún objeto nuevo hereda R1/R2/R3.
